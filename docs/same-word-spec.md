# 同詞相遇：默契崩壞版（`same-word`）規格草案

> 狀態：設計草案（v3：2–12 人、依配對輪次分默契等級、剩一人頒「與眾不同」、僅中文與英文（不處理簡體）），尚未實作 | 日期：2026-10-30
> 參考：http://samewordgame.hikawa00.top/（同词相遇）
> 房間：沿用 `server/room`（`registerRoomHandlers`），不修改共用模組

---

## 1. 參考遊戲看到了什麼

網站首頁只公開了「建房設定」和一句流程說明，**局內畫面與判定細節沒有公開**，下面標「推測」的是未經驗證的部分。

| 項目 | 來源遊戲 | 備註 |
|---|---|---|
| 流程 | 每人同時想一個詞 → 同時揭曉 → 全部相同即「通關」；否則看著大家的詞繼續聯想，下一輪 | 網站文字 |
| 勝利 | 同一輪所有人寫出同一個詞 | 網站文字 |
| 人數 | 私人房 2 或 3 人 | 網站文字 |
| 思考時間 | 30 秒 / 60 秒 / 自訂 | 網站文字 |
| 邀請 | 建房後產生連結，或輸入房間碼 | 網站文字 |
| 相同詞判定（同義詞、繁簡） | 未說明 | 推測是字串完全比對 |
| 回合上限、計分 | 未說明 | 推測無上限、不計分 |

**我們要改的地方**：原版 2–3 人時「誰跟誰不合」很明顯；人多（最多 12 人）後全員同詞變得很難，而且玩家真正想知道的是「**誰跟誰最有默契、誰跟誰是死對頭**」。所以這版保留原版核心循環，另外加上**兩兩配對的等級**：第 1 輪就同詞是「天生一對」，越晚配對成功默契越低，始終沒配對的是「死對頭」，結算時給整桌的默契榜。

## 2. 規則

### 2.1 一局流程

```
waiting ──開始──▶ writing ──全員送出／時間到──▶ revealed ──┬─ 未配對者 ≤ 1 人 ─▶ finished
                    ▲                                      ├─ 達回合上限 ────▶ finished
                    └────────────── 下一輪 ◀───────────────┘
```

1. **writing**：所有人（包含已配對成功的人）同時寫一個詞（預設 45 秒）。伺服器只告訴大家「誰已送出」，不下發內容。
2. **revealed**：全員送出或時間到 → 同時揭曉所有詞，並標示相同的詞分成哪幾組。停留數秒（房主按「下一輪」，或自動倒數）。
3. **已配對**：玩家只要曾與任何一人寫出相同詞，就是「已配對」（之後仍繼續參與，可和別人再配出新的一對）。
4. **結束判定**（揭曉後依序檢查）：
   - **未配對者 ≤ 1 人** → 結束。剩 1 人：頒 🦄 **與眾不同**；剩 0 人（含全員同詞）：沒有人落單。
   - 達回合上限 → 結束。此時若未配對者剛好 1 人，同樣頒「與眾不同」；2 人以上則各自為 🐺 孤狼。
   - 否則下一輪，第 2 輪起畫面上只顯示「上一輪」各人寫的詞當線索（本輪要同時和它們有關），更早的輪次不再顯示。
5. 回合上限預設 8 輪（可選 5 / 8 / 12 / 不限）。
6. 2 人局：兩人第一次同詞時，未配對者為 0 → 立刻結束，結算就是那一對的稱號。

### 2.2 詞的限制與「相同」判定

**可輸入**：中文字與英文字母（A–Z、a–z），可混用（如「iPhone手機」）。長度 1–12 字，頭尾空白會被去掉。
**不可輸入**：日文假名、注音符號、數字、標點與表情符號。違規時送出被拒絕，提示「請輸入中文或英文」，**前端與伺服器都要檢查**（伺服器為準）。

**簡體字**：本遊戲**不支援也不偵測簡體**，不新增任何簡繁轉換依賴。字元檢查只看 Unicode 範圍（中日韓統一表意文字 `U+4E00–U+9FFF` + 英文字母），簡體字落在同一範圍所以不會被擋，但「蘋果」與「苹果」會被視為不同的詞。玩家之間自行約定用正體。

**「相同」＝正規化後字串完全一致**：
- 不做簡繁轉換、不做同義詞。
- 英文不分大小寫（`Apple` = `apple`，已確認），全形英文先轉半形。
- 逾時未送出視為空白，**空白不等於任何詞，包含另一個空白**。

### 2.3 兩兩默契：以「第幾輪配對成功」決定等級（本版核心）

對每一對玩家 (A, B) 記錄**第一次寫出相同詞的輪次** `firstMatch(A,B)`，從未相同則為 `∞`。**越早配對成功，默契越高**；每一輪揭曉時，只要有人「新配對成功」，當場宣告該對的稱號與默契值。

| 第幾輪首次相同 | 稱號 | 默契值 |
|---|---|---|
| 第 1 輪 | 💘 天生一對 | 100% |
| 第 2 輪 | ✨ 心有靈犀 | 85% |
| 第 3 輪 | 🤝 默契十足 | 70% |
| 第 4 輪 | 😊 還算合拍 | 55% |
| 第 5 輪 | 🌱 慢熟型 | 40% |
| 第 6 輪 | 🔧 需要磨合 | 30% |
| 第 7 輪 | 😅 勉強同頻 | 20% |
| 第 8 輪以後 | 🩹 差點錯過 | 10% |
| 從未相同 | 💔 死對頭 | 0% |

稱號與數值是 `gameLogic.js` 檔頭的常數表（`CHEMISTRY_TIERS`），之後可直接調整，不看回合上限。已配對過的兩人之後再寫出相同詞不會重新宣告，也不會改變默契值（只記一次）。

**一個詞有 3 人以上同詞時**：不逐對列出（12 人最多 66 對），揭曉畫面只顯示「N 人同心」群組標籤；若群組內有「新配對」，標出其中最高等級的稱號，完整的兩兩稱號放結算矩陣。

**結算榜**

| 項目 | 算法 |
|---|---|
| 💘 最佳拍檔 | 默契值最高的配對（可並列，最多列 3 組） |
| 💔 頭號死對頭 | 從未相同的配對中，依序比：①兩人互相投對方「離譜」的票數 ②兩人各自的總配對成功數（越少越糟）③固定雜湊（保證結果可重現）。列前 3 組 |
| 🦄 與眾不同 | 結束時唯一沒有配對成功的玩家（頭銜大字置頂，列在最佳拍檔之前） |
| 🐺 孤狼 | 達回合上限時，未配對者有 2 人以上，這些人各自為孤狼 |
| 🧲 磁鐵 | 其他人下一輪寫的詞等於他本輪的詞，累計次數最多者 |
| 🛸 離譜王 | 累計被同桌票選「最離譜的詞」次數最多者（見 2.4） |
| 📊 個人默契指數 | 每位玩家與所有他人配對的默契值平均（死對頭算 0%）；也可點開看自己和每個人的稱號 |

> 為什麼不用語意相似度：需要詞向量或 LLM，成本與延遲高、結果難解釋。以上指標只靠「相同／不同」與玩家票選，結果可複算，玩家也看得懂。若日後想做，再當選配。

**平手與邊界**
- **2 人局**：只有一對，這一對的稱號就是結算；沒有「最差」榜，只顯示稱號與默契值。
- 因為「未配對者 ≤ 1 人」就結束，遊戲常在多數人都配對後收尾；**結束當下沒同詞過的配對一律記 0%（💔 死對頭）**，所以 12 人局的熱力圖會有大量 0% 格，這是預期結果，死對頭榜只取前 3 組。房主仍可按「提前結算」。
- 3 人局很可能第 1 輪兩人同詞就結束，剩下的那一位直接是「與眾不同」。
- 中途離開／被踢的人：該玩家之後的輪次從所有配對中排除；已離開者不進入結算榜，但他已成立的配對保留在歷史中（顯示為已離場）。
- 同一輪某人逾時（空白）：該輪不參與配對，也不記離譜票。

### 2.4 離譜票（選配，預設開）

揭曉後 8 秒內，每人可點一個**別人的詞**投「最離譜」（不能投自己，可不投）。只用來當並列時的 tie-break 與「離譜王」，不影響配對與結束判定。

### 2.5 可選設定（建房 `options`）

| 選項 | 值 | 預設 |
|---|---|---|
| `timerSeconds` | 30 / 45 / 60 / 自訂 15–180 | 45 |
| `maxRounds` | 5 / 8 / 12 / 0（不限） | 8 |
| `starterMode` | `free`（自由）／`seed`（開局隨機給 2 個詞當第 0 輪線索） | `free` |
| `outlierVote` | true / false | true |

玩家數 2–12（`maxPlayers` 2–12）。人越多越難通關，大廳依人數建議輪數上限：2–4 人 8 輪、5–8 人 10 輪、9–12 人 12 輪（僅預填，可改）。

## 3. 架構（全部沿用現有慣例）

### 3.1 檔案

```
server/same-word/
  gameLogic.js        純函式：createGame / submitWord / settleRound / pairStats / buildView / buildResult
  gameLogic.test.js   node --test
  index.js            registerNamespace(io, db)：呼叫 registerRoomHandlers + sw:* 事件
  seedWords.js        starterMode=seed 用的種子詞（可先 30 組）
vue-app/src/apps/same-word/
  pages/SameWordLobbyPage.vue、SameWordRoomPage.vue
  components/  WriteBox / RevealBoard / HistoryStrip / ResultBoard / PairMatrix
  composables/useSameWord.js    （建立在 shared/composables/useRoom.js 之上）
  data/phases.js
```

登記處：`server.js` 掛載、`router/index.js` 兩條路由、`apps/portal/data/tools.js` 一筆（`id` 必須等於 `rooms.app_id` = `'same-word'`）。

### 3.2 房間 hooks

| Hook | 設定 |
|---|---|
| `minPlayers` | 2 |
| `canJoinAsPlayer` | 僅 `waiting` / `finished`；其他階段進觀戰席 |
| `spectatorCanUpgrade` | 僅 `waiting` / `finished` |
| `buildGameState` | 回傳 `buildView`（重連時還原階段、倒數、已送出名單、歷史輪） |
| `onPlayerLeft` | 從本局移除；若只剩 1 人 → 中止回到 waiting；若離開者是最後一個沒送出的 → 立即結算本輪 |

遊戲狀態只放記憶體（同血染鐘樓）；server 重啟後房間回到大廳。

### 3.3 遊戲狀態與資訊隱藏

```js
game = {
  phase: 'waiting' | 'writing' | 'revealed' | 'finished',
  options: { timerSeconds, maxRounds, starterMode, outlierVote },
  round: 3,
  roundEndsAt: 1730000000000,          // 伺服器時間戳，前端自己算倒數
  seed: ['海', '夏天'] | null,
  rounds: [                             // 已揭曉的輪次
    { words: { [playerId]: '西瓜' }, groups: [['a','c'],['b']], outlierVotes: { [playerId]: targetId } }
  ],
  pending: { [playerId]: '西瓜' },      // 本輪已送出內容（只存在伺服器）
  activeIds: [...],                     // 本局參與者（開始時鎖定）
  result: null | { endReason: 'allPaired' | 'maxRounds' | 'host', unique, loners, bestPairs, worstPairs, magnet, outlier, matrix }
  // unique: 與眾不同者的 playerId 或 null
}
```

`buildView(game, viewerId)` 規則：
- `writing`：只下發 `submitted: { [id]: boolean }` 與**自己**送出的詞；別人的詞絕不下發。
- `revealed` 之後才下發 `rounds[n].words`。
- 側通道：「誰已送出」會下發（UX 需要），但**不下發送出時間**，避免從先後推測誰「很快就想到」。

### 3.4 Socket 事件（namespace `/same-word`，前綴 `sw:`）

| 方向 | 事件 | Payload |
|---|---|---|
| C→S | `sw:start` | —（僅房主，≥2 人） |
| C→S | `sw:finish-now` | —（僅房主，提前結算） |
| C→S | `sw:submit` | `{ word }`（writing 階段可改，直到鎖定） |
| C→S | `sw:vote-outlier` | `{ targetId }`（revealed 階段） |
| C→S | `sw:next-round` | —（房主；或全員點準備） |
| C→S | `sw:restart` | —（房主，finished 後回 waiting） |
| S→C | `sw:state` | 每人專屬視圖 |
| S→C | `sw:error` | `{ code, message }` |

計時到 0 由伺服器切階段（與血染鐘樓不同，本遊戲節奏緊湊，必須自動）。計時器只放在 `index.js`，`gameLogic` 只接收 `now`。

## 4. 前端畫面

1. **大廳**：暱稱 + 建房（人數 2–12、計時、輪數上限）／加入（房間碼）；支援 `?room=` 分享連結。遵循〈房間系統統一規範〉的 Lobby 流程。
2. **書寫**：中央大輸入框 + 圓形倒數 + 玩家頭像一圈（已送出亮起）；上方 `SwPrompt` 只顯示上一輪各人的詞（第 1 輪顯示開局線索或提示）。
3. **揭曉**：所有詞翻牌；相同的詞用同色分組；新配對成功時跳出稱號卡（例如「小明 × 小華　💘 天生一對 100%」），等級越高動畫越誇張；底部離譜票。12 人時詞卡用網格排列，群組顯示「N 人同心」。
4. **結算**：🦄 與眾不同（若有，全螢幕頭銜）→ 💘 最佳拍檔 → 💔 頭號死對頭（大字）→ 🐺 孤狼 → 🧲 磁鐵 → 🛸 離譜王 → 📊 個人默契指數 → 可展開的 N×N 默契熱力圖（顏色對應默契值，點格子看稱號）。
5. 字級、Tailwind 4、Reka UI 彈窗、不可 `<style scoped>`，沿用 `docs/STRUCTURE.md` 與統一規範第十章。

### 必備測試案例（P1）

| 輸入 | 期望 |
|---|---|
| 3 人同輪寫「西瓜 / 西瓜 / 西瓜」 | 通關，3 對皆 `firstMatch=1`，皆「天生一對 100%」 |
| 4 人：第 1 輪 A=B、C≠D；第 2 輪 A=C=B | A-B 天生一對 100%；第 2 輪 A-C、B-C 心有靈犀 85%（A-B 不重複宣告）；此時只剩 D 未配對 → 結束，D 與眾不同 |
| 8 輪都沒通關，C 從未與 A 相同 | 失敗；A-C 為 `∞` → 死對頭 0% |
| 2 人第 3 輪同詞 | 通關；唯一一對「默契十足 70%」；無「最差」榜 |
| 12 人第 1 輪 5 人同詞 | 產生 C(5,2)=10 對 100%，揭曉只顯示「5 人同心」群組；矩陣內 10 格皆 100% |
| 第 9 輪才首次相同 | 默契值 10%（第 8 輪以後同值） |
| 死對頭並列 | 依互投離譜票 → 總配對數 → 固定雜湊，重跑結果相同 |
| 3 人第 1 輪 A=B≠C | 結束；C 為「與眾不同」；A-B 天生一對；A-C、B-C 死對頭 0% |
| 12 人，第 3 輪後只剩 1 人未配對 | 結束；該人「與眾不同」，無孤狼 |
| 達上限仍有 2 人未配對 | 兩人皆孤狼，無「與眾不同」 |
| 達上限恰剩 1 人未配對 | 該人「與眾不同」 |
| 最後一個未配對者在同一輪與他人配對 | 未配對 0 人，結束，無與眾不同 |
| 輸入「123」「かな」「ㄅㄆ」「a b!」 | 全部拒絕；「蘋果」「iPhone手機」通過 |
| 「蘋果」與「苹果」 | 通過檢查，但視為不同的詞 |
| `Apple` 與 `apple`、`ＡＰＰＬＥ` | 視為相同 |
| 玩家全程無人配對且 ≥2 人未配對 | 孤狼，個人默契指數 0% |
| 兩人都逾時（空白） | 不算相同 |
| 「Apple」與「apple 」「蘋果」 | 前兩者相同，第三者不同 |
| 玩家第 3 輪離開 | 之後配對排除；結算榜不含該玩家 |
| 離開者之後的輪次 | 不產生新配對；已成立的配對保留 |
