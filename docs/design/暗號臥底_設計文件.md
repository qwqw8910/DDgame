## 1. Objective

### 背景

「甜甜的小秘密」平台已有兩款多人遊戲：

| 遊戲 | 玩法核心 |
|------|---------|
| 懂我再說 | 互動選擇猜測 |
| 默契傳聲筒 | 協力提示猜詞（全體合作） |

兩者皆為合作/非對抗性玩法。本遊戲引入**社交推理元素**（Social Deduction），增加欺騙與反欺騙的張力。

### 遊戲概念

每回合，一位玩家背後有一個題目詞（自己看不到）。其餘玩家被秘密分配「**好人（綠卡）**」或「**臥底（黑卡）**」陣營：

- **好人（Red Team）**：誠實給提示，幫助猜題者猜對
- **臥底（Black Team）**：偽裝好人，故意給誤導性提示讓猜題者猜錯

猜題後，全員投票揪出臥底。這是一場「猜字」與「抓鬼」的雙重博弈。

### 使用者故事

- 身為猜題者，我想根據他人給的提示猜出我背後的詞，並猜出誰是臥底，獲得最高個人分數
- 身為好人，我想給清楚的提示幫助猜題者猜對，同時識破臥底的誤導並投票揪出他
- 身為臥底，我想給看似合理但實際誤導的提示讓猜題者猜錯，並且在投票中不被懷疑

## 5. 遊戲規則設計

### 5.1 人數配置與臥底分配

| 總人數 | 猜題者 | 好人數 | 臥底數 | 說明 |
|-------|-------|-------|-------|------|
| 3 人 | 1 人 | 1 人 | 1 人 | 1v1v1，心理壓力極大 |
| 4–5 人 | 1 人 | 2–3 人 | 1 人 | 最佳平衡 |
| 6–8 人 | 1 人 | 4–5 人 | 2 人 | 臥底可互相掩護 |

> ⚠️ **每回合重新分配**好人/臥底身份（本輪猜題者不參與分配，只擔任猜題角色）。
> 表格中的「好人數」與「臥底數」為 N-1 位非猜題者中的分配比例。

### 5.2 大廳流程

1. 輸入暱稱 → 建立房間（產生 6 碼房號）或貼入房號加入
2. 等待玩家到齊（顯示已加入人數 / 最大人數）
3. 房主按「開始遊戲」（最少 3 人才能開始）
4. 後端決定猜題順序（按 join_order）；**身份於每回合開始前分配**

### 5.3 身份確認階段（每回合開始時觸發）

每回合開始時，後端先將本輪猜題者以外的所有玩家重新分配好人/臥底身份，再廣播 `wc:identity`。

```
後端廣播 wc:round-start（含猜題者是誰）
  │
  ▼ 後端分別傳送 wc:identity 給各非猜題玩家（本人 socket 專屬）
  │
  ▼ 前端：畫面顯示一張寬大的黑色翻面卡片
  │
  └─ 提示文字：「請確認四下無人，點擊查看你本輪的秘密身份」
       │
       ▼ 玩家點擊 / 長按
  卡片翻轉動畫（0.4 秒）
       │
       ├─ 好人（綠卡）：「🟢 好人  你是紅隊隊員！誠實給提示，幫猜題者得分。」
       ├─ 臥底（黑卡）：「🃏 臥底  你是黑隊密探！誤導猜題者，完美隱藏身份。」
       │       │（若有 2 個臥底）└─「你的臥底隊友是：[暱稱]」
       └─ 猜題者（灰卡）：「🎯 猜題者  這回合輪到你！等提示出來後填入你的答案。」

  1.5 秒後（或手指/滑鼠移開後）自動蓋回，防止旁人偷看
       │
       ▼
  點擊「我已確認身份」按鈕 → 告知後端（wc:identity-confirmed）
  全員確認後，房主出現「開始提示階段」按鈕
```

### 5.4 回合進行流程

> **階段推進原則**：每個階段均設 **60 秒**倒數作為上限，但**由房主的按鈕決定何時切換**到下一階段。60 秒到期時系統將強制推進（等同房主按下按鈕）。

```
回合開始
  │
  ▼
後端推播：wc:round-start（含本輪猜題者、回合編號）
  └─ 後端同步傳送 wc:identity 給各非猜題者（本輪身份已重新抽取）
  └─ 後端傳送 wc:word 給非猜題者（猜題者 socket 不收此事件）
  │
  ▼
【身份確認階段】（見 §5.3）倒數 60 秒
  全員查看各自的身份卡並點擊確認
  └─ 全員確認 or 60 秒到期 → 解鎖房主的「開始提示」按鈕
  房主點擊「開始提示」→ emit wc:advance-phase
  │
  ▼
【提示階段】倒數 60 秒
  所有非猜題者（好人 & 臥底）同時在各自輸入框填入提示
  限制：最多 10 個字元；一個詞或短語
  ├─ 送出後：自己的提示顯示已鎖定 ✓；其他人只看到「某人已提交 ✓」（不顯示內容）
  └─ 全員送出 or 60 秒到期 → 提示攔位自動鎖定；解鎖房主的「揭曉提示」按鈕
  房主點擊「揭曉提示」→ emit wc:advance-phase
  │
  ▼
【揭曉提示 / 猜題階段】倒數 60 秒
  後端廣播 wc:hints-revealed，所有提示同時顯示
  介面：卡片排列，每張卡顯示提示者暱稱 + 提示詞
  猜題者在輸入框填入答案並送出
  └─ 猜題者送出 or 60 秒到期 → 後端廣播 wc:guess-result；解鎖房主的「開始投票」按鈕
      ├─ 猜對：畫面大字顯示「🎉 答對了！」
      └─ 猜錯：畫面大字顯示「💀 答錯了！答案是：[XXXX]」
  房主點擊「開始投票」→ emit wc:advance-phase
  │
  ▼
【投票階段】倒數 60 秒
  全員（含猜題者）各投一票「你認為誰是臥底？」
  ├─ 送出後：自己的票已鎖定 ✓；其他人只看到「某人已投票 ✓」（不顯示投給誰）
  └─ 全員投完 or 60 秒到期 → 投票攔位鎖定；解鎖房主的「揭曉結果」按鈕
  房主點擊「揭曉結果」→ emit wc:advance-phase
  │
  ▼
【回合結算】
  後端廣播 wc:round-result
  ├─ 揭曉各票投給誰（視覺化票數）
  ├─ 揭曉臥底身份
  ├─ 本回合得分明細（誰得幾分、原因）
  └─ 累積排行榜
  解鎖房主的「下一回合」按鈕
  房主點擊「下一回合」→ emit wc:advance-phase
  │
  ▼
若仍有人未當過猜題者 → 回到「回合開始」（後端重新分配身份）
若全員輪過一次 → wc:game-over（全局結算）
```

### 5.5 計分規則（方案 A：雙重博弈制）

| 觸發事件 | 得分者 | 分數 | 說明 |
|---------|-------|-----|------|
| 猜題者猜對 | 猜題者 | +3 | 主要得分 |
| 猜題者猜對 | 所有好人 | +1 各 | 協力成功獎勵 |
| 猜題者猜錯 | 所有臥底 | +2 各 | 搗亂成功 |
| 投票正確指出臥底 | 投票給臥底的人 | +1 各 | 識破臥底 |
| 猜題者投票指出臥底 | 猜題者 | 額外 +2 | 猜中兼抓鬼 |
| 臥底未被投票最高票揭露 | 所有臥底 | +3 各 | 隱藏成功 |

**「被揭露」的判定**：
- 投票結束後，得票**最高**的玩家若是臥底 → 臥底「被揭露」
- 若最高票是好人 → 臥底「隱藏成功」（+3）
- 多人同分最高票時：最高票群組中**有任何一位臥底**→ 臥底「被揭露」；全是好人 → 臥底「隱藏成功」

**全局 MVP**：所有人輪過猜題者後，個人積分最高者獲得 MVP 稱號。

## 6. Socket 事件規格

### Client → Server

| 事件 | 參數 | 說明 |
|------|------|------|
| `wc:create` | `{ roomId, playerId, nickname, maxPlayers }` | 建立房間 |
| `wc:join` | `{ roomId, playerId, nickname }` | 加入房間 |
| `wc:start` | — | 房主開始遊戲（後端決定猜題順序，身份於每回合分配） |
| `wc:identity-confirmed` | — | 玩家確認已看過本回合身份 |
| `wc:advance-phase` | — | **房主專用**：推進到下一階段（提示→猜題→投票→結算→下一回合） |
| `wc:submit-hint` | `{ hint: string }` | 提交提示（非猜題者用） |
| `wc:submit-guess` | `{ guess: string }` | 猜題者提交答案 |
| `wc:submit-vote` | `{ targetPlayerId: string }` | 投票指認臥底 |

### Server → Client

| 事件 | 接收方 | 參數 | 安全重點 |
|------|--------|------|---------|
| `wc:room-state` | 本人（重連） | `{ room, players, phase, roundNo, leaderboard }` | 不含身份、題目 |
| `wc:identity` | **本人** | `{ role: 'good' \| 'wolf' \| 'guesser', wolfPartners?: [{ playerId, nickname }] }` | ⚠️ 每回合推送，只傳給本人 |
| `wc:round-start` | 所有人 | `{ roundNo, guesserId, guesserName, timerSeconds: 60 }` | — |
| `wc:word` | **非猜題者** | `{ word: string }` | ⚠️ 猜題者 socket 不收 |
| `wc:phase-changed` | 所有人 | `{ phase, timerSeconds: 60 }` | 房主推進後廣播新階段 |
| `wc:hint-submitted` | 所有人 | `{ playerId, nickname }` | 只通知「誰已提交」，不含內容 |
| `wc:hints-revealed` | 所有人 | `{ hints: [{ playerId, nickname, hint }] }` | 全體同時揭曉 |
| `wc:guess-result` | 所有人 | `{ correct: boolean, answer: string }` | — |
| `wc:vote-submitted` | 所有人 | `{ playerId }` | 只通知「誰已投票」，不含投給誰 |
| `wc:round-result` | 所有人 | `{ votes, wolves, scores, leaderboard }` | — |
| `wc:game-over` | 所有人 | `{ leaderboard, mvp }` | — |
| `wc:error` | 請求者 | `{ code, message }` | — |

## 7. 安全性規範

| 資訊 | 流向規則 |
|------|---------|
| 玩家身份（`role`） | 後端只透過 `wc:identity` 傳給**本人 socket**；`isWolf` 布林值不出現在廣播事件中 |
| 臥底隊友名單 | 只傳給臥底本人（`wolfPartners` 欄位在 `wc:identity` 中） |
| 本輪題目（`word`） | 只透過 `wc:word` 傳給**非猜題者**；猜題者 socket 不收此事件 |
| 他人提示內容 | 在 `wc:hints-revealed`（全員鎖定後）才廣播；`wc:hint-submitted` 只廣播「誰已送出」 |
| 投票對象 | 在 `wc:round-result`（投票結束後）才揭露；`wc:vote-submitted` 只廣播「誰已投票」 |

**後端驗證**：
- 所有操作先驗證 `socket.data.playerId` 是否屬於該房間
- `wc:submit-hint` 驗證請求者非本回合猜題者
- `wc:submit-guess` 驗證請求者是本回合猜題者
- `wc:start` / `wc:advance-phase` 驗證請求者是房主
- `wc:advance-phase` 驗證當前階段可合法推進（例如不可在猜題者尚未送出前強制跳到投票）

## 8. Code Style

### 後端模組

```javascript
// server/wolf-clue/index.js
'use strict';

const { registerRoomHandlers } = require('../room');

function registerNamespace(io, db) {
  const ns = io.of('/wolf-clue');

  ns.on('connection', (socket) => {
    socket.on('wc:start', () => {
      const { playerId, roomId } = socket.data;
      // 驗證房主 → 決定猜題順序 → 廣播第一回合（身份在此分配）
    });

    socket.on('wc:advance-phase', () => {
      const { playerId, roomId } = socket.data;
      // 驗證房主 → 驗證當前階段可推進 → 廣播 wc:phase-changed
    });

    socket.on('wc:submit-hint', ({ hint }) => {
      // 驗證非猜題者 → 儲存提示 → 廣播已送出標記
    });
  });
}

module.exports = { registerNamespace };
```

## 9. Testing Strategy

**手動測試（3 個瀏覽器分頁模擬 3–4 玩家）：**

| 分類 | 測試場景 |
|------|---------|
| **基本流程** | 建立/加入房間 → 開始 → 每人收到自己本回合的身份 |
| **身份重分配** | 每回合的 `wc:identity` 事件傳送正確（上一回合是臥底，這回合可能換成好人）|
| **身份安全** | DevTools Network：玩家 A 的 `wc:identity` 中不含玩家 B 的 role |
| **題目安全** | 猜題者的 Network Log 中不出現 `wc:word` 事件 |
| **提示同步** | 提示階段中，後送出的人看不到前人的提示內容；全員送出後同時揭曉 |
| **投票隱私** | 投票期間只看到「誰已投票」；結算後才顯示各票流向 |
| **計分驗算** | 造出「猜對 + 抓到鬼」、「猜錯 + 鬼隱藏成功」等情境，對照計分表核算 |
| **房主推進** | 各階段房主按鈕出現時機正確（未全員確認前買「開始提示」按鈕不可用）|
| **60 秒強制推進** | 計時到期後，無需房主操作，系統自動進入下一階段 |
| **輪換** | 3 人局：3 回合後進入全局結算；每回合身份重新分配；排行榜 MVP 正確 |
| **斷線重連** | 提示階段離線再重連，收到 `wc:room-state` 可恢復到正確階段 |
| **房間錯誤** | 加入不存在的房號、滿房、重複暱稱 → 正確顯示錯誤訊息 |

## 10. Boundaries

### Always
- 身份、題目、提示（未揭曉前）、投票（未結算前）只在正確時機傳給正確玩家
- 所有操作先驗證 `socket.data.playerId`
- 事件名稱使用 `events.js` 常數（`wc:` 前綴）
- 臥底判定、計分邏輯全在後端計算

### Ask First
- 修改計分規則（分數數值調整）
- DB schema 變更（欄位新增/修改）
- 修改每局長度定義（從 1 輪改為可設定 1–2 輪）
- 增加新的身份類型（如第三陣營）

### Never
- 前端接收其他玩家的身份資訊（含是否為臥底）
- 猜題者在提示揭曉前收到 `word`
- 已送出的提示在全員鎖定前廣播內容
- 已投出的票在回合結算前廣播對象

## 11. Success Criteria

### Must-Have

- [ ] 3–8 人可完整跑完一局（每人各猜一次，全局結算正確）
- [ ] 臥底身份不洩漏給其他玩家（Network Level 驗證）
- [ ] 猜題者收不到本輪題目
- [ ] 提示在全員送出（或計時到期）後同時揭曉
- [ ] 計分依規則正確計算並顯示明細
- [ ] 投票結束後正確揭曉臥底並結算本回合
- [ ] 全局排行榜顯示 MVP
- [ ] 斷線重連可恢復到當前階段

### Nice-to-Have

- [ ] 2 個臥底時可見「臥底專屬文字聊天室」（提示提交前可用）
- [ ] 回合記錄存入 `wolf_clue_rounds` 表供日後分析
- [ ] 房主可設定「玩 2 輪」（每人猜 2 次）
